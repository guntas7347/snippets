Adding a New IIS + Next.js Site

Deployment guide for hosting a Next.js standalone application behind IIS URL Rewrite and PM2 on Windows Server.

1. Create the Proxy Directory

Create a directory for the site under:

C:\inetpub\ignet\site-proxy\<site-name>
  1. Copy the existing working web.config into the new directory.
  2. Edit the copied file so the hostname matches the new site and the reverse-proxy target uses that application's Node.js port.
  3. Keep the existing rewrite and proxy settings unless the new site specifically needs a change.
Important: Use a unique local Node.js port for every application. The IIS proxy target, launcher port, and application configuration must agree.

2. Configure IIS

  1. Open IIS Manager and choose Sites → Add Website….
  2. Set the site name to <site-name>.
  3. Set the physical path to C:\inetpub\ignet\site-proxy\<site-name>.
  4. Add an HTTP binding for the hostname on port 80.
  5. Add an HTTPS binding for the hostname on port 443, and select the wildcard SSL certificate. Enable SNI if required by the server's existing binding setup.

Allow the forwarded-host server variable

IIS URL Rewrite must be allowed to set HTTP_X_FORWARDED_HOST before the site's rewrite rule can assign it.

  1. In IIS Manager, select the server node (the top-level machine, not just the new website).
  2. Open URL Rewrite.
  3. Choose View Server Variables… in the Actions pane.
  4. Choose Add…, enter HTTP_X_FORWARDED_HOST, then confirm.
  5. Open the new site's web.config and ensure the reverse-proxy rule sets the forwarded-host header. Keep the rule syntax consistent with the existing working configuration.
<serverVariables>
  <set name="HTTP_X_FORWARDED_HOST" value="{HTTP_HOST}" />
</serverVariables>

The snippet above belongs inside the relevant URL Rewrite rule's action configuration; do not paste it as a standalone top-level section. If the existing configuration already has a <serverVariables> section, add the setting there rather than creating a duplicate.

3. Build the Next.js App

Run these commands in Bash from the application's project directory:

npm run build

mkdir -p .next/standalone/.next
cp -r .next/static .next/standalone/.next/
cp -r public .next/standalone/

If the project has no public directory, skip the final copy command. These commands assume the Next.js project uses output: "standalone" in its configuration.

4. Create the Launcher

Create server-start.cjs in the project root, alongside the .next directory:

process.env.NODE_ENV = "production";
process.env.PORT = "3050";
process.env.HOSTNAME = "127.0.0.1";

require("./.next/standalone/server.js");

Change 3050 to the unique port assigned to this application. Make sure the IIS reverse-proxy target uses the same port.

5. Start the Site with PM2

From the project directory, run:

pm2 start ./server-start.cjs --name "<site-name>"
pm2 save

Use a consistent PM2 process name, such as the hostname or site name, so deployments can restart the correct process.

6. Deploy Subsequent Updates

After pulling or applying code changes, run these commands from the same project directory:

npm run build

mkdir -p .next/standalone/.next
cp -r .next/static .next/standalone/.next/
cp -r public .next/standalone/

pm2 restart "<site-name>"

If there is no public directory, omit its copy command. If the build changes dependencies, install the required production dependencies before restarting.

Final Verification

  • ☐ The IIS site's physical path points to the correct proxy directory.
  • ☐ HTTP and HTTPS bindings use the intended hostname.
  • ☐ The wildcard certificate is selected for HTTPS.
  • ☐ HTTP_X_FORWARDED_HOST is registered under IIS URL Rewrite → View Server Variables.
  • ☐ The proxy rule forwards requests to the correct Node.js port and passes the forwarded-host variable.
  • ☐ The PM2 process is online and the application responds on 127.0.0.1:<port>.
  • ☐ The public hostname works over HTTPS and static assets load.
Keep a known-good copy of the existing web.config before editing it. Use the current working proxy configuration as the baseline for every new site.
